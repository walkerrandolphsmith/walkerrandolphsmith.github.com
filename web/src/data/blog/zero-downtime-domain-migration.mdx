## TL;DR

I moved my personal site from my old domain, `walkerrandolphsmith.com`, to the shorter `walkersmith.me`.

Zero downtime  
Seamless redirects  
Preserved SEO ranking  
Full HTTPS coverage

## Why Migrate?

I used the domain `walkerrandolphsmith.com` for more than ten years. But it was long, difficult to spell, and easy to forget. The new domain, `walkersmith.me`, is shorter, easier to remember, and better aligned with my personal brand.

But this was more than a cosmetic change. I had to keep the site available, prevent search ranking penalties, and make sure that every old link continued to work.

## What Was in Place

**Azure Static Web Apps** hosts my site. I managed the old domain through **App Service Domains** with an **Azure DNS Zone**.

Azure App Service Domains does not support `.me` top-level domains (TLDs). So I bought `walkersmith.me` through **GoDaddy**.

I considered pointing the APEX (`@`) of the new domain to the static IP of the Azure Static Web App. But that would bypass Azure Front Door and limit performance and security. It would also create duplicate content across domains, which is a big SEO risk.

So I needed a robust solution, secured with HTTPS. It had to redirect all traffic, including paths, to the new domain.

## The Strategy

### 1. Set Up Azure Front Door in Front of the Old Site

Azure Front Door (AFD) became the global edge entry point.

- Created a **Front Door profile**
- Added `walkerrandolphsmith.com` and `www.walkerrandolphsmith.com` as **custom domains**
- Verified domain ownership and waited for the automatic issue of **TLS certificates**
- In the **Azure DNS Zone**, I pointed:
  - `@` (APEX) to the Front Door endpoint with an **alias A record**
  - `www` to the Front Door with a **CNAME**

Result: zero downtime, secure traffic, and a fast global edge.

### 2. Move `walkersmith.me` DNS from GoDaddy to Azure

- Created a **new Azure DNS Zone** for `walkersmith.me`
- Added `walkersmith.me` and `www.walkersmith.me` as **custom domains** in Front Door
- Completed domain validation and waited for the HTTPS certificates
- In the Azure DNS Zone:

  - Pointed `@` to the same AFD endpoint with an **alias A** record
  - Pointed `www` to the AFD endpoint with a **CNAME**

  > This step is **critical**. I did not switch the nameservers in GoDaddy immediately. I **first repeated all of Step 1 for `walkersmith.me`**:

  > I used commands such as `nslookup -type=CNAME walkersmith.me ns1-08.azure-dns.com`. They verified that all DNS records resolved correctly through the authoritative Azure name servers before I made any change live.

- Updated GoDaddy nameservers

This prevented downtime during the switch. Azure Front Door could handle traffic immediately after GoDaddy delegated authority.

### 3. Wait for Propagation

Name server changes can take up to **48 hours**, but they usually propagate within an hour.

During that time:

- The old domain (`walkerrandolphsmith.com`) already sent traffic through Front Door
- The new domain (`walkersmith.me`) was ready in the background
- After propagation completed, AFD handled both domains seamlessly

### 4. Redirect with Rule Sets (301s)

- Created a **Rule Set** named `redirect-legacy` in AFD
- Added a rule to:
  - Match requests where the `Host` is `walkerrandolphsmith.com` or `www.walkerrandolphsmith.com`
  - Apply a **301 redirect** to the same path on `walkersmith.me`

This makes sure that deep links such as `/blog` or `/about` redirect correctly, not only the homepage.

### 5. Canonical Tags

In the Next.js app, I added a `<link rel="canonical">` tag to each page with dynamic metadata:

```ts
export const metadata = genPageMetadata({
  title: 'Blog',
  canonical: 'https://walkersmith.me/blog',
})
```

This tells search engines which version of the content is primary. It prevents duplicate indexing penalties.

## Verifying the Redirects

Use these tools to verify:

- `nslookup walkersmith.me` → Shows Azure DNS nameservers
- `curl -I -L -v http://walkerrandolphsmith.com/blog` → Follows:
  - 307 redirect (HTTP → HTTPS)
  - 301 redirect to `walkersmith.me/blog`
  - 200 response from the new domain

Everything works, cleanly and transparently.

## Final Thoughts

Domain migrations are often stressful and risky, with many SEO problems.

But you can modernize your brand **without breaking a single link** if you use:

- Azure Front Door
- Careful DNS delegation
- Canonical metadata
- Verified 301 redirects

**No downtime. No ranking drop.**
